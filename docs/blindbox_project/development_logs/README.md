使用规则：

- 只记录已经发生并完成排查的问题，不替代产品、架构、测试或发布文档。
- 每条日志应包含：时间、现象、影响、根因、修复、验证、后续动作。
- 后续研发 agent 遇到类似问题时，优先阅读对应日志，再决定是否修改产品/架构/代码。
