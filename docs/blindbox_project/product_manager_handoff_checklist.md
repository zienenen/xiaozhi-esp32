## 2. 已确认产品结论

| 编号 | 结论 | 当前影响 |
| --- | --- | --- |
| D-01 | 当前优先完成课题主线 | 课题一期 P0 优先于市场化完整商业闭环 |
| D-02 | 市场化方向需要保留 | 角色池、单设备单智能体、原厂绑定、管理端能力不能被破坏 |
| D-03 | 景区数据集/向量库管理页列为课题一期 P0 | 架构和全栈必须给出数据集状态展示与知识关联方案 |
| D-04 | 一期 Demo 只要求 1 个景点点位完整跑通 | 多点位配置放 P1，路线规划放 P2 |
| D-05 | 手动模拟打卡页进入一期 P0 | 无硬件或调试阶段可联调，模拟记录必须与真实记录区分 |
| D-06 | 课题一期采用 GPS 粗定位 + NFC 精准打卡 | GPS 只负责接近提醒，NFC 是打卡成功依据 |
| D-07 | 管理页面需要适配 PC、平板、手机 | 三端页面不能被整体推到二期 |
| D-08 | 每台硬件机器人只能绑定一个智能体 | 设备详情、绑定页、演示页状态必须一致 |
| D-09 | 后期只能由原厂后台更换绑定角色 | 普通用户不提供角色自由切换入口 |
| D-10 | 市场化目标用户为 18-26 岁潮玩用户 | 不以儿童/亲子作为市场化主线 |

## 3. 课题一期 P0 交接清单

| 模块 | P0 产品要求 | 验收口径 | 下一责任角色 |
| --- | --- | --- | --- |
| 设备身份 | 设备具备唯一 device_id / SN | 后台或配置能识别指定设备 | 架构师、全栈工程师 |
| 角色绑定 | 单设备绑定单智能体 | 同一设备不存在多个当前角色 | 架构师、全栈工程师 |
| 角色配置 | 角色有人设、音色、知识库引用 | 设备播报和问答体现角色差异 | 产品经理、全栈工程师 |
| 景区数据 | 至少 1 个景区数据集进入演示 | 页面能看到数据集状态、chunk 数量、关联角色/点位 | 架构师、全栈工程师 |
| 向量检索 | 景区资料完成拆分和向量化 | 问答能基于指定景区资料，不是通用闲聊 | 架构师、全栈工程师 |
| 点位配置 | 1 个景点点位完整跑通 | 可配置点位名称、坐标、GPS 半径、NFC 标签 | 架构师、全栈工程师 |
| GPS 粗定位 | 进入范围后触发接近提醒 | 页面或设备能显示已接近，需要 NFC 确认 | 全栈工程师 |
| NFC 精准打卡 | 合法 NFC 标签完成打卡 | 非法、停用、未绑定标签不能成功 | 全栈工程师 |
| 打卡记录 | 最近打卡记录可查看 | 展示设备、角色、点位、NFC、时间、结果、失败原因 | 全栈工程师 |
| 手动模拟 | 测试账号可模拟坐标/NFC | 模拟记录有明确标记，不混入真实记录 | 全栈工程师、研发主管 |
| 三端页面 | PC/平板/手机可查看核心状态 | 不出现核心信息遮挡，PC 可完成核心配置 | 全栈工程师 |
| 演示页面 | 展示设备、角色、GPS、NFC、打卡结果 | 非研发人员能看懂 Demo 是否跑通 | 产品经理、全栈工程师 |

## 4. 市场化保留边界

| 模块 | 当前处理 | 不进入课题一期的内容 |
| --- | --- | --- |
| 多性格角色池 | 保留字段和产品口径 | 不要求完整角色运营后台 |
| 单实体单智能体 | 与课题绑定能力共用 | 不开放用户自由切换 |
| 开盒揭晓 | 保留为市场化主流程 | 课题一期不强制做完整开盒仪式 |
| 稀有款/隐藏款 | 角色页可预留 series、rarity | 不做抽盒概率、订单、支付 |
| 用户资产 | 后续市场化评估 | 不做收藏柜、会员、二级交易 |
| GPS/NFC 活动 | 作为市场化附带场景 | 不作为市场化一期主卖点 |

## 7. 交接结论

产品侧当前已经明确：课题一期不是只做硬件接 GPS，也不是只做一个后台列表，而是要跑通“景区数据定制化智能体 + GPS 粗定位 + NFC 精准打卡 + 三端管理/演示页面 + 单设备单智能体绑定”的最小闭环。

后续角色补文档时，不能把以下内容整体下放到二期：

1. 景区数据集/向量库状态展示；
2. 单点位 GPS/NFC 打卡闭环；
3. PC/平板/手机三端核心页面；
4. 手动模拟打卡联调入口；
5. 打卡记录最小可查看能力；
6. 单设备绑定单智能体的管理和展示。
