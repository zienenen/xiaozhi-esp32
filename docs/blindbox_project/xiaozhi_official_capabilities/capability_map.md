# 小智官网能力地图

文档状态：draft  
主责智能体：架构师智能体  
更新时间：2026-07-13

## 0. 文档目的

本文用于把“小智官网/官方链路能力”拆成可分析、可替代、可回退的能力项。

注意：本文不评价官网页面 UI，也不要求像素级复刻。这里关注的是：哪些能力是我们业务必须掌握的，哪些能力可以继续依赖官网，哪些能力需要在商业化阶段自研。

## 1. 能力分层

```text
L0 固件与设备本体
L1 设备接入与配置
L2 语音链路与智能体会话
L3 MCP / 工具调用
L4 业务配置与运营数据
L5 运维、安全、OTA 和商业化治理
```

## 3. 我方必须掌握的主数据

以下数据必须以我方后端为主，不应长期只维护在小智官网：

- `device_id`、设备 SN、设备业务状态。
- 设备与角色绑定关系。
- 角色名称、人设 prompt、voice_id 引用、状态。
- 景区、景点、点位、NFC 标签。
- 景区知识库、知识摘要、问答素材。
- GPS 接近事件和 NFC 打卡记录。
- 小智工具调用我方接口的业务日志。

## 4. 可以短期继续依赖官网的能力

一期和过渡阶段可以继续依赖：

- 设备语音接入。
- ASR/LLM/TTS 编排。
- 基础设备上线和语音连接。
- 官网侧 MCP/工具入口配置。
- 官网侧必要的模型、音色、智能体基础配置。

这些能力不作为我方业务主数据来源。

## 5. 不建议一期自研的能力

- 完整设备激活体系。
- 完整配网 App/小程序。
- 自建实时语音服务端。
- 多模型调度平台。
- 固件 OTA 灰度和回滚平台。
- 多租户、计费、企业审计。

原因：这些能力工作量大，且会分散一期景区打卡和角色业务闭环。

## 6. 架构结论

当前最合理的边界是：

```text
官网继续承载语音底座
我方先承载业务主数据和配置源
MCP/工具作为连接两边的过渡层
设备配置拉取作为转自研第一抓手
```
