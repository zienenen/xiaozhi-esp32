# 小智官网自研替代框架：全栈交接说明

文档状态：draft  
主责智能体：架构师智能体  
更新时间：2026-07-13

## 0. 交接目的

本文把架构师定义的双轨框架拆成全栈工程师可识别的模块边界。

本文不要求全栈立即全部实现，只说明模块该放哪里、先做什么、哪些属于后置。

## 1. 建议工程模块

当前仍沿用单仓多模块：

```text
main/                         固件
backend/                      Django/DRF 后端
frontend/                     React/Vite 管理端和演示页
tools/device_simulator/       设备模拟器
deploy/                       部署示例
docs/blindbox_project/        项目资料
```

## 2. 后端模块映射

| 能力 | 建议 app | 当前状态 | 说明 |
| --- | --- | --- | --- |
| 设备档案/绑定 | `devices` | 已有 app 目录 | 增加配置版本、同步状态、官网引用 ID |
| 角色控制台 | `agents` | 已有 app 目录 | 保存 prompt、voice_id、知识库引用 |
| 景点/点位 | `spots` | 已有 app 目录 | 保存 GPS 半径、点位和播报文案 |
| NFC 标签 | `nfc_tags` | 已有 app 目录 | 标签和点位绑定 |
| 打卡记录 | `checkins` | 已有 app 目录 | 幂等、来源、定位质量 |
| 数据集/知识 | `datasets` | 已有 app 目录 | 一期摘要，后续向量检索 |
| 演示聚合 | `demo` | 已有 app 目录 | 演示看板和模拟打卡 |
| MCP 工具管理 | 建议后续新增 `tools_registry` 或放入 `agents` 子模块 | 待建 | S3 阶段建设 |
| 官网同步状态 | 可先放 `agents`/`devices` 字段 | 待建 | 不单独建大模块 |

## 3. 前端页面映射

| 页面 | 阶段 | 功能 |

## 4. 固件侧边界

固件侧建议只做以下集成点：

- 启动时拉取设备配置。
- 保存最近一次可用配置。
- GPS 接近提醒。
- NFC 读卡确认。
- 打卡事件上报。
- 配置拉取失败时走本地缓存或静态配置。

固件侧不建议做：

- 复杂角色管理。
- 景区知识检索。
- 语音服务编排。
- 官网配置同步。
- OTA 平台逻辑。

## 6. 回退实现要求

全栈实现时必须保留以下兜底点：

- 后端接口失败：前端显示接口异常，不伪造成成功。
- 设备配置失败：固件使用本地缓存或静态配置。
- 小智工具失败：固定播报兜底。
- 知识库查询失败：返回可播报的默认文案。
- 打卡上报失败：设备本地缓存，后续补传。

## 7. 下一步可拆任务

建议研发主管拆成以下任务包：

| 任务包 | 说明 |
| --- | --- |
| T1 设备配置中心 | 后端聚合配置、前端展示配置版本、模拟器拉取配置 |
| T2 角色控制台 | 角色 prompt、voice_id、知识库引用、绑定关系 |
| T3 官网工具桥接验证 | 用 `X-Tool-Token` 验证 context 和 knowledge 接口 |
| T4 MCP 工具管理草案 | 工具定义表、调用日志表、测试页面 |
| T5 固件配置拉取 | 设备启动拉取配置、本地缓存、失败兜底 |

其中 T1-T3 可以服务当前 Demo，T4-T5 视硬件和排期推进。
