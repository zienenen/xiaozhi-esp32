## 1. 产品定位

市场化方向面向 18-26 岁、对潮玩/IP/盲盒/情绪消费有兴趣的年轻用户，尝试把“静态潮玩”升级为“会回应、会陪伴、有人格的 AI 实体角色”。

产品形态可以概括为：

> 盲盒多性格 AI 智能体 + 单一实体机器人

用户购买的是一个实体机器人。每台机器人出厂绑定一个唯一性格/角色智能体，用户开盒后获得一个固定角色，不能自由切换。产品感知上不是“一个可以换角色的语音工具”，而是“这个实体机器人就是这个角色”。

该方向可以理解为“AI 智能体结合拉布布式盲盒商业模式”：用潮玩盲盒机制制造期待感、稀缺感和社交传播，用 AI 对话能力让角色从静态摆件变成可持续互动的实体陪伴对象。

传统潮玩解决的是“我喜欢它、我想拥有它、我愿意展示它”；AI 盲盒实体机器人希望进一步解决“它会回应我、它像一个固定角色陪在我身边、我和它之间会产生关系”。这使产品不只停留在一次性开盒兴奋，而有机会形成持续互动、内容运营和角色复购。

## 1.1 方向判断

这个方向的机会在于三类趋势正在交汇：

| 趋势 | 说明 | 产品机会 |
| --- | --- | --- |
| 潮玩 IP 年轻化 | 年轻用户愿意为角色审美、稀缺性和社交表达付费 | 用盲盒机制和角色池建立购买动机 |
| 情绪消费日常化 | 用户越来越愿意购买能带来陪伴、治愈、表达自我的产品 | 用固定性格智能体提供持续情绪价值 |
| AI 交互实体化 | AI 不只存在于 App，也可以进入桌面、房间、包挂、礼物等实体场景 | 用实体机器人承载 AI 角色人格 |

因此，本产品不是“给潮玩加一个聊天功能”，而是尝试创造一种新的 AI 潮玩形态：

> 用户抽到的不是一个模型，也不是一个软件账号，而是一个有固定人格、固定声音、固定身份的实体 AI 角色。

## 1.2 产品愿景

短期目标是验证年轻用户是否愿意为“固定性格的 AI 实体角色”产生兴趣、互动和购买意愿。

中期目标是形成可持续扩展的角色池：普通款、稀有款、隐藏款、联名款、节日款，让每个角色都具备独特人设、声音、台词和互动风格。

长期看，这个方向可以从单个 AI 盲盒机器人，扩展为一个“实体 AI 角色宇宙”：用户可以收集不同角色，分享开盒和对话，参与线下活动，购买联名系列，并在不同场景中与自己的实体角色建立长期关系。

## 1.3 与普通 AI 硬件的差异

| 对比对象 | 普通 AI 硬件 | 本产品方向 |
| --- | --- | --- |
| 核心卖点 | 工具能力、问答效率、硬件参数 | 角色人格、盲盒惊喜、情绪价值 |
| 用户关系 | 用户使用一个设备 | 用户拥有一个角色 |
| 角色切换 | 通常可以切换助手/音色 | 用户不可自由切换，强化唯一性 |
| 购买理由 | 功能是否好用 | 角色是否想拥有、想晒、想互动 |
| 复购逻辑 | 硬件升级 | 收集不同角色、稀有款、联名款 |
| 分享点 | 功能演示 | 开盒揭晓、角色金句、人格反差 |

## 1.4 当前小智项目可复用能力

市场化方向不是从零开发硬件语音机器人，而是基于小智 ESP32 开源项目已有能力做产品化改造。完整现状分析见 [xiaozhi_existing_capabilities_analysis.md](xiaozhi_existing_capabilities_analysis.md)。

| 已有能力 | 对市场化方向的价值 |
| --- | --- |
| 语音输入/输出 | 支撑角色对话、开盒揭晓、角色金句播报 |
| ASR + LLM + TTS 链路 | 支撑多性格角色智能体的基础对话能力 |
| Wi-Fi / 4G 网络能力 | 支撑设备获取绑定角色、角色配置和后台管理 |
| 设备状态机 | 可接入首次启动、角色加载、待机、说话等流程 |
| OLED/LCD 显示和通知 | 可展示角色名、状态、简单反馈 |
| 本地音效 | 可用于开盒、成功、提醒等反馈 |
| 多板卡适配 | 便于选择硬件快速做市场化 Demo |
| MCP 工具系统 | 可扩展设备状态、角色配置、原厂控制能力 |
| OTA/资源更新 | 后续可更新固件、角色资源、音效和配置 |

## 2. 目标用户

| 用户类型 | 年龄/特征 | 核心动机 | 典型场景 |
| --- | --- | --- | --- |
| 潮玩盲盒用户 | 18-26 岁，关注潮玩/IP/限量款 | 收集、开盒、晒图、获得稀缺感 | 购买盲盒、分享开盒、交换收藏 |
| 情绪陪伴用户 | 18-26 岁，愿意为情绪价值付费 | 想要一个有性格、有声音、有回应的实体陪伴对象 | 桌面陪伴、睡前聊天、碎片化互动 |
| 社交表达用户 | 喜欢在小红书、抖音、朋友圈表达生活方式 | 通过角色表达审美、性格和圈层身份 | 晒图、录屏、分享角色金句 |
| 礼品消费用户 | 给朋友、伴侣、同学购买有趣礼物 | 礼物需要有新鲜感、话题性和互动性 | 生日、节日、纪念日 |
| 渠道/合作方 | 潮玩店、文创店、快闪活动、电商渠道 | 推出具备 AI 互动能力的新型潮玩产品 | 联名款、限定款、线下活动 |

> 注：亲子、景区、研学不是市场化主线目标用户，可作为后续垂直场景扩展。

## 3. 核心产品原则

| 原则 | 说明 |
| --- | --- |
| 单一实体绑定单一智能体 | 每台机器人只能对应一个角色智能体，强化角色唯一性 |
| 用户不可自由切换角色 | 保留盲盒机制、稀缺性和收藏价值 |
| 角色先于功能 | 用户首先喜欢的是角色，不是参数和工具能力 |
| AI 强化潮玩留存 | AI 对话用于让角色持续“活着”，不是做通用助手 |
| 开盒必须有仪式感 | 首次启动要像“揭晓角色”，形成传播点 |
| 性格必须有记忆点 | 不做泛泛的温柔/活泼，要有人格张力和口头禅 |
| 管理端一期必须存在 | 原厂需要配置设备、角色、绑定关系和基础内容 |

## 4. 一期核心闭环

| 步骤 | 用户/系统行为 | 目标 |
| --- | --- | --- |
| 1 | 用户获得实体机器人 | 形成“开盒期待” |
| 2 | 首次开机 | 设备联网并识别自身 device_id |
| 3 | 后台返回绑定角色 | 确认该实体机器人对应哪个 agent_id |
| 4 | 机器人揭晓角色 | 通过声音/台词展示“你抽到了谁” |
| 5 | 用户开始对话 | 角色按固定人设、口吻、音色回应 |
| 6 | 用户产生分享欲 | 角色金句、反差、开盒过程具备传播性 |
| 7 | 原厂后台可管理 | 原厂能查看设备、角色、绑定和内容配置 |

## 5. 功能需求清单

### 5.1 盲盒角色池

| 功能编号 | 功能 | 描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- | --- |
| M-A01 | 多性格角色池 | 平台预置多个差异明显的角色智能体 | P0 | 至少有 3 个角色，性格和声音可明显区分 |
| M-A02 | 角色唯一标识 | 每个角色有 agent_id | P0 | 后台可通过 agent_id 管理角色 |

| M-A04 | 角色人设 | 每个角色有性格、口头禅、互动风格、边界设定 | P0 | 同一问题不同角色回答风格不同 |
| M-A05 | 角色稀缺度 | 支持普通款、稀有款、隐藏款等概念 | P1 | 一期可先在配置中预留字段 |

### 5.3 开盒与首次启动体验

| 功能编号 | 功能 | 描述 | 优先级 | 验收标准 |

## 11. 验收指标

| 指标 | 验收方式 |
| --- | --- |
| 角色揭晓成功 | 首次开机后机器人能说出绑定角色身份 |
| 绑定稳定 | 重启后仍为同一角色 |
| 性格差异明显 | 3 个角色回答同一问题时风格明显不同 |
| 音色差异明显 | 3 个角色声音可被用户区分 |
| 基础对话可用 | 用户可完成不少于 3 轮连续语音互动 |
| 用户不可切换 | 用户侧无角色切换入口 |
| 管理端可配置 | 原厂可配置设备、角色、绑定关系 |
| 三端可用 | PC/平板/手机均可访问管理端核心功能 |

## 13. 与课题方向的关系

市场化方向和课题方向共用底层智能硬件平台，但需求叙事不同。

| 共用能力 | 市场化表达 | 课题表达 |
| --- | --- | --- |
| 小智 ESP32 语音底座 | AI 实体角色载体 | 开源智能硬件语音交互底座 |
| 角色智能体 | 盲盒多性格 IP | 多智能体人设配置 |
| 设备绑定 | 一个实体机器人对应一个智能体 | 设备身份和智能体绑定机制 |
| 管理端 | 原厂角色和设备绑定工具 | 系统配置与实验观测平台 |
| GPS/景区能力 | 后续场景扩展 | 课题核心场景能力 |
