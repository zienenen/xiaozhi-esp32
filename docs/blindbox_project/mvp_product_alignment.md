## 1. MVP 总体判断

当前 MVP 采用双轨产品策略：

1. **课题 MVP 当前优先交付**：用于完成项目申报、演示、技术验证和阶段性成果展示。
2. **市场化 MVP 作为后续主方向保留**：当前不作为第一交付闭环，但产品定义、用户定位和复用能力需要持续纳入设计。

该策略的原因：

- 课题方向已有明确一期范围：1 台自装机器人、GPS 粗定位、NFC 精准打卡、角色化播报、三端页面。
- 市场化方向需要更多用户、价格、渠道、外观、IP 和合规调研，不适合在课题一期中强行扩大。
- 两个方向共用底层能力：小智语音底座、设备身份、角色绑定、角色人设、音色、管理端。

长期路线补充：

- 当前平台不是小智官网完整平替，一期允许继续把小智官网/官方链路作为不可见依赖。
- 后期商业化需要逐步对标小智官网的设备接入、智能体配置、工具管理、固件交付、OTA、账号权限和语音服务能力。
- 对标不是终点，最终目标是在小智设备智能体平台能力之上，增加盲盒角色、单实体单智能体、出厂绑定、稀有款/隐藏款、角色 IP 运营和线下触发玩法。
- 一期自研平台必须成为配置源和展示主界面：角色 prompt、voice_id、知识库引用在我方平台设置，再人工或半自动同步到小智官网；对话记录、同步状态和内容来源需要在我方平台可见。

## 2. 双轨 MVP 定义

| 方向 | MVP 名称 | 一句话定义 | 当前状态 |
| --- | --- | --- | --- |
| 课题方向 | 景区打卡智能体演示 MVP | 基于小智 ESP32 的语音角色机器人，通过 GPS 判断接近点位，再用 NFC 精准确认打卡，并触发角色化播报和问答 | 当前一期优先 |
| 市场化方向 | AI 盲盒实体角色 MVP | 面向 18-26 岁潮玩用户，一个实体机器人绑定一个固定性格智能体，强调开盒、角色唯一性、声音、人设和陪伴对话 | 后续主方向，当前保留需求池 |

## 4. 后续市场化 MVP 目标用户

| 用户 | 需求 | 后续 MVP 需要满足 |
| --- | --- | --- |
| 18-26 岁潮玩用户 | 想拥有一个有性格、有声音、有稀缺感的 AI 实体角色 | 开盒揭晓、固定角色、专属音色、可分享对话 |

| 渠道/合作方 | 需要新型 AI 潮玩产品 | 角色池、绑定管理、系列化运营能力 |

## 5. 课题一期主流程

```text
设备上电
  -> 联网并进入小智语音链路
  -> 从我方平台加载固定角色配置
  -> 我方平台展示角色 prompt、voice_id、知识库引用和官网同步状态
  -> GPS 获取当前位置
  -> 判断是否接近演示点位
  -> 提示用户靠近 NFC 标签
  -> NFC 读取并校验合法标签
  -> 生成打卡成功事件
  -> 角色化语音播报
  -> 用户继续进行景点/点位相关问答
  -> 我方平台记录对话内容和知识来源
  -> 管理端/展示页查看定位、打卡和设备状态
```

## 6. 市场化后续主流程

```text
用户购买实体机器人
  -> 开盒并首次启动
  -> 设备获取出厂绑定角色
  -> 机器人用专属声音揭晓角色
  -> 用户与固定角色进行陪伴对话
  -> 用户产生分享/收藏/复购意愿
  -> 原厂通过管理端维护角色、设备和绑定关系
```

## 9. 当前非目标

| 非目标 | 适用方向 | 原因 |
| --- | --- | --- |
| 完整用户 App | 课题一期 | 当前三端 Web 足够演示和管理 |
| 商城/支付/订单 | 课题一期、市场化当前阶段 | 需要后续商业调研 |
| 用户资产/收藏柜 | 当前阶段 | 需要用户体系和商业模式确认 |
| 二级市场/交易 | 当前阶段 | 合规和商业风险高 |
| 多景区路线规划 | 课题一期 | 当前先验证 1 个点位触发，多点位为 P1 |
| 地图导航 | 课题一期 | 不是核心演示价值 |
| 长期记忆成长 | 当前阶段 | 会显著增加数据和安全复杂度 |
| 角色屏幕形象/动画 | 当前阶段 | 用户已确认暂不需要 |

## 10. 产品验收标准

### 10.1 课题 MVP 验收

| 验收项 | 通过标准 |
| --- | --- |
| 设备启动 | 设备可上电、联网、进入语音链路 |
| 角色加载 | 设备能使用固定角色配置 |
| GPS 粗定位 | 设备可读取定位或通过模拟坐标进入演示 |
| NFC 精准打卡 | 合法标签触发打卡成功，非法标签不触发 |
| 防重复 | 同一点位短时间内不重复播报 |
| 角色播报 | 打卡成功后有角色化语音反馈 |
| 展示页面 | PC/平板/手机可查看设备和打卡状态 |
| 演示完整性 | 可连续演示“启动 -> 定位 -> NFC -> 打卡 -> 播报 -> 问答” |
| 景区数据问答 | 用户提问时，回答能基于指定景区数据集形成，不是通用闲聊 |
| 手动模拟打卡 | 测试账号可在无硬件或调试阶段模拟坐标/NFC，模拟记录与真实记录可区分 |
| 对话记录 | 页面可查看设备、角色、用户输入、AI 回复、点位、知识片段摘要、时间和来源 |
| 官网同步状态 | 角色配置页或同步页能展示 prompt、voice_id、工具地址等是否已同步到小智官网 |
| 同步操作留痕 | 每次人工或半自动同步有操作人、时间、对象、结果和失败原因 |

### 10.2 市场化后续验证

| 验证项 | 通过标准 |
| --- | --- |
| 用户定位 | 明确 18-26 岁潮玩用户为主目标 |
| 角色差异 | 至少 3 个角色在人设、音色、金句上有明显差异 |
| 绑定逻辑 | 一个实体机器人绑定一个智能体，用户不可切换 |
| 开盒体验 | 首次启动能让用户感知抽中固定角色 |
| 分享动机 | 角色台词、声音或反差具备录屏/晒图价值 |
