## 1. 当前产品口径

当前项目采用“双轨产品口径”：

| 方向 | 当前优先级 | 当前定位 |
| --- | --- | --- |
| 课题方向 | 当前一期优先 | 以三坊七巷为单测试景区，建设多模态文旅数据库，并通过具身智能讲解机器人验证传播效果 |
| 市场化方向 | 后续最主要方向，当前需兼顾 | 面向 18-26 岁潮玩用户的盲盒多性格 AI 智能体 + 单一实体机器人 |

本阶段优先完成课题一期，因为它有明确研究对象、建库主体、演示闭环、硬件采购清单和技术验证路径。市场化方向不被放弃，相关需求应保留在需求池中，并明确哪些能力可由课题一期复用。

课题一期的产品口径需要特别注意：数据库建设是核心主体，讲解机器人是传播应用载体，GPS/NFC 是场景触发手段，不应把课题简化成“机器人打卡 Demo”。

## 2. 能力复用关系

| 课题一期能力 | 对市场化方向的关系 | 说明 |
| --- | --- | --- |
| 小智 ESP32 语音底座 | 共用底座 | 市场化实体机器人也需要语音输入、TTS 播放、联网和状态机 |
| 单设备绑定单角色 | 共用核心能力 | 课题演示和市场化盲盒都需要 device_id -> agent_id |
| 角色人设与音色 | 共用核心能力 | 市场化强调多性格，课题强调角色化讲解 |
| 管理端三端适配 | 共用管理能力 | 两个方向都需要最小管理端，但管理对象不同 |
| 多模态内容库 | 市场化内容运营可复用 | 市场化后续角色故事、联名内容、活动内容也需要标准化内容库 |
| GPS 粗定位 | 市场化附带/后续场景能力 | 市场化一期不以 GPS 为主线，但可作为线下活动、景区、快闪触发能力 |
| NFC 精准打卡 | 市场化附带/后续场景能力 | 可用于线下活动、限定点位、互动任务，但不是市场化一期核心卖点 |
| 景区数据向量库 | 课题核心，市场化场景扩展 | 市场化主线不依赖景区知识，但景区联名版本可复用 |

## 5.1 小智官网对标能力优先级

本节用于给研发主管、架构师和后续全栈工程师提供产品侧优先级。这里不定义技术实现、工期或团队分工。

当前产品判断：

- 我们当前平台不是小智官网完整平替，而是基于小智 ESP32 固件和官方语音链路之上的业务增强平台。
- 后期商业化目标是逐步对标小智官网的核心设备智能体平台能力，并在此基础上增加盲盒角色、出厂绑定、稀有款、角色 IP 运营和线下触发玩法。
- 一期课题 Demo 可以继续使用小智官网/官方链路作为不可见依赖，但商业化长期不能把设备、角色、业务数据和运营控制权长期留在外部平台。

### 5.1.1 对标优先级口径

| 优先级 | 定义 |
| --- | --- |
| P0 | 我们商业化必须掌握的业务控制权，也是课题一期或市场化核心闭环不能丢的能力 |
| P1 | 近期对标小智控制台的核心能力，能明显减少人工配置和官网依赖 |
| P2 | 商业化前必须补齐的平台能力，进入真实批量设备后会成为基础设施 |
| P3 | 完全私有化或重型平台能力，涉及语音服务、设备云、计费、多租户等长期能力 |

### 5.1.2 能力清单

| 编号 | 对标能力 | 小智官网/官方链路做的事 | 我们当前缺口 | 产品优先级 | 产品验收口径 |
| --- | --- | --- | --- | --- | --- |
| XZ-P0-01 | 设备业务档案 | 官网可围绕设备进行管理和配置 | 我们已有业务设备页雏形，但需要形成长期设备主档 | P0 | 后台可管理 device_id、SN、绑定角色、在线状态、版本摘要 |
| XZ-P0-02 | 单设备单智能体绑定 | 官网侧可配置设备与智能体关系 | 我们必须自研并作为盲盒核心逻辑 | P0 | 一台设备同一时间只能绑定一个 agent_id，普通用户不可切换 |
| XZ-P0-03 | 角色/智能体配置源 | 官网可配置智能体、提示词等 | 我们需要保存自己的角色名称、人设 prompt、音色引用、知识库引用 | P0 | 后台可编辑 2 个以上角色，设备或演示链路能读取对应配置 |
| XZ-P0-04 | 业务知识库/数据集 | 官网不是我方景区知识主库 | 我们需要自研三坊七巷多模态数据集和向量检索入口 | P0 | 数据集、chunk、知识点、关联角色/点位状态可见，可用于问答 |
| XZ-P0-05 | 景区/GPS/NFC 业务闭环 | 官网不承载我方打卡业务 | 我们需要自研点位、NFC、打卡记录和演示页 | P0 | 1 个点位跑通 GPS 接近、NFC 确认、角色播报和记录展示 |
| XZ-P0-06 | 自研演示/管理端 | 官网控制台不能作为我方对外展示主界面 | 我们需要 PC/平板/手机可用的业务管理页面 | P0 | 对外演示只展示我方页面，核心状态非研发人员可理解 |
| XZ-P0-07 | 对话记录 | 官网或语音链路产生的对话不能只留在外部平台 | 我们需要在自研平台展示设备、角色、用户输入、AI 回复、点位、知识片段摘要、时间和来源 | P0 | 后台可查看最近对话记录，并能说明回答来自哪个角色和哪类知识来源 |
| XZ-P0-08 | 官网同步状态 | 当前 prompt、voice_id、工具地址可能仍需人工配置到小智官网 | 我们需要在自研平台记录待同步、已同步、失败、最后同步时间、操作人和备注 | P0 | 每个角色至少能看到官网同步状态，不需要登录官网也能判断配置是否完成 |
| XZ-P0-09 | 官网同步内容快照 | 小智官网仍作为执行侧时，需要知道应复制哪些配置 | 我们需要生成角色 prompt、voice_id、知识库/工具地址等同步内容快照 | P0 | 平台可展示或复制本次应同步到官网的配置内容 |
| XZ-P0-10 | 官网同步操作记录 | 人工或半自动同步过程需要留痕 | 我们需要记录同步操作人、同步时间、同步对象、配置版本、结果和失败原因 | P0 | 同步失败时能看到原因；同步成功后能追溯谁在何时同步了什么 |
| XZ-P1-01 | 设备配置下发 | 官网/官方链路给设备下发连接与配置 | 我们缺完整自研配置中心 | P1 | 设备或模拟器可从我方后台拉取角色、点位、NFC、数据集摘要 |
| XZ-P1-02 | 设备在线状态和心跳 | 官网能感知设备在线和连接状态 | 我们需要把业务侧在线状态做稳定 | P1 | 后台能看到最近心跳、最近 GPS、最近打卡和异常状态 |
| XZ-P1-03 | MCP/工具管理 | 官网可配置工具或相关调用入口 | 我们需要自研工具清单、调用入口和状态展示 | P1 | 后台可查看工具名称、用途、调用地址、启用状态和最近调用结果 |
| XZ-P1-04 | 工具调用日志 | 官网侧日志我方不可完全掌控 | 我们需要记录业务工具调用和失败原因 | P1 | 可查看上下文接口、知识检索、打卡接口的调用时间和结果 |
| XZ-P1-05 | 官网配置辅助/迁移 | 当前可能仍需人工在小智官网配置 | 我们需要减少人工配置成本 | P1 | 形成配置清单、复制字段或半自动同步说明，降低联调出错 |
| XZ-P1-06 | 角色配置版本 | 官网配置变化可能不可追溯 | 我们需要角色 prompt、音色、知识库引用版本记录 | P1 | 后台可看到角色配置版本和最近更新时间 |
| XZ-P2-01 | 设备激活/绑定流程 | 官网负责设备码、账号和激活链路 | 我们缺自研激活和账号绑定体系 | P2 | 新设备可通过我方流程完成激活、归属、绑定和状态初始化 |
| XZ-P2-02 | 固件包管理 | 小智提供固件下载和不同板卡烧录包 | 我们缺自有固件包中心 | P2 | 后台可管理板卡型号、固件版本、下载包、变更说明和适用设备 |
| XZ-P2-03 | 烧录指引/交付流程 | 小智有面向用户的烧录教程或工具链 | 我们缺标准烧录交付路径 | P2 | 研发/生产人员能按我方文档完成烧录、验机、绑定和交付 |
| XZ-P2-04 | OTA/配置版本升级 | 小智固件已有 OTA/资源更新基础 | 我们缺商业化级 OTA 管理 | P2 | 可按设备或批次管理升级版本、失败状态和回退策略 |
| XZ-P2-05 | 设备安全凭据 | 官网/官方链路承担部分鉴权 | 我们需要自建设备 token、签名、轮换策略 | P2 | 设备调用我方接口不依赖明文裸 token，日志不泄露密钥 |
| XZ-P2-06 | 多账号权限和审计 | 官网有账号控制台，我方一期只有演示账号 | 我们缺原厂、运营、内容、只读等权限 | P2 | 不同角色账号有不同操作边界，关键操作有审计记录 |
| XZ-P3-01 | 自建语音服务端 | 小智承载 ASR/LLM/TTS 和实时通信 | 我们当前依赖外部语音链路 | P3 | 具备自研或私有化语音网关、模型编排、TTS/ASR 配置和监控 |
| XZ-P3-02 | 完整设备云 | 小智承载设备长连接、协议、状态和消息 | 我们缺完整设备云平台 | P3 | 支持批量设备长连接、在线管理、消息下发、断线恢复和监控 |
| XZ-P3-03 | 多租户/商业后台 | 小智官网面向多用户平台化 | 我们当前只做项目和演示后台 | P3 | 支持组织、项目、客户、套餐、额度、运营看板等平台级能力 |
| XZ-P3-04 | 计费/套餐/限流 | 官网或商业平台通常需要资源治理 | 我们暂不涉及 | P3 | 可按设备、模型、调用量或客户维度做额度和限流 |

### 5.1.3 产品推进建议

| 阶段 | 产品目标 | 优先级范围 |
| --- | --- | --- |
| 阶段 1：课题与业务闭环 | 用我方页面证明三坊七巷多模态数据、角色智能体、GPS/NFC 打卡、对话记录、官网同步状态和演示闭环 | 完成 P0 |
| 阶段 2：控制台对标 | 把小智官网里和角色、设备、工具配置相关的高频运营能力逐步迁回我方 | 推进 P1 |
| 阶段 3：商业化设备平台 | 面向真实批量设备，补齐激活、固件包、烧录、OTA、权限和安全凭据 | 推进 P2 |
| 阶段 4：完整私有化平台 | 在商业化规模和客户需求明确后，再考虑自建语音服务、设备云、多租户和计费 | 评估 P3 |

## 10. 一期非功能与验收边界

| 类别 | 一期要求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| 三端适配 | 管理与演示页面适配 PC、平板、手机 | P0 | 三类屏幕均可完成核心查看，PC 可完成核心配置 |
| 页面可用性 | 设备、角色、绑定、景点、NFC、数据集、打卡记录均有可见入口 | P0 | 管理员不需要改代码即可查看核心状态 |
| 演示可解释 | 实时演示页能展示 GPS、NFC、角色、点位、打卡结果 | P0 | 非研发人员能看懂演示是否成功 |
| 调试兜底 | 手动模拟打卡页进入一期 | P0 | 无硬件或 GPS 不稳定时仍可联调完整流程 |
| 模拟数据隔离 | 模拟打卡必须有明确标记 | P0 | 真实记录和模拟记录可区分 |
| 权限边界 | 测试/模拟入口仅测试或原厂账号可见 | P0 | 演示查看者不可误触发模拟数据 |
| 数据集可解释 | 景区数据集状态、chunk 数量、角色/点位关联可见 | P0 | 能证明智能体使用指定景区数据，不是泛化闲聊 |
| 多模态可解释 | 文本、图像、音频资源的知识点关联可见 | P0 | 能证明讲解机器人调用的是标准化多模态数据库，不是单一文本库 |
| 对话可追溯 | 对话记录能展示设备、角色、用户输入、AI 回复、点位、知识片段摘要、时间和来源 | P0 | 能证明内容沉淀在我方平台，而不是只存在于小智官网 |
| 同步可解释 | prompt、voice_id、工具地址等官网同步内容和状态可见 | P0 | 能证明我方平台是配置源，小智官网只是执行侧或语音链路侧 |
| 绑定一致性 | 一个设备同一时间只能绑定一个智能体 | P0 | 设备详情、演示页、绑定页状态一致 |
| 失败可诊断 | GPS 无信号、NFC 无效、设备离线、数据集失败等状态可见 | P0 | 页面能给出明确失败原因 |
| 安全与隐私 | GPS、设备 ID、绑定关系不得公开暴露给无权限用户 | P0 | 权限外页面不可查看敏感状态 |
