## 3. 产品前提

### 3.1 当前优先级

一期优先完成课题主线：

> 基于小智 ESP32 开源项目，构建景区数据定制化智能体，并通过 GPS 粗定位 + NFC 精准打卡完成指定地点触发交互的 Demo。

市场化主线需要在一期设计中保留扩展口径：

> 面向 18-26 岁潮玩用户，形成 AI 盲盒多性格智能体 + 单一实体机器人 + 出厂绑定角色的商业化产品方向。

### 3.2 三端定义

这里的“三端”是响应式 Web 产品形态，不代表必须开发三套独立系统。

| 端 | 主要对象 | 一期定位 |
| --- | --- | --- |
| PC 管理端 | 原厂管理员、项目管理员、测试人员 | 管理设备、角色、景点、NFC、打卡记录 |
| 平板端 | 展示现场、评审现场、景区演示人员 | 查看演示状态、打卡结果、设备在线状态 |
| 手机端 | 现场调试人员、演示辅助人员 | 快速查看设备状态、打卡结果、必要时执行测试操作 |

## 4. 用户角色

| 角色 | 权限诉求 | 一期是否必须 |
| --- | --- | --- |
| 原厂管理员 | 设备绑定、角色绑定、基础配置管理 | P0 |
| 项目管理员 | 景点、NFC 标签、打卡记录管理 | P0 |
| 演示查看者 | 查看设备状态和打卡结果 | P0 |
| 研发调试人员 | 查看异常状态，进行有限模拟操作 | P0 |
| 市场运营人员 | 管理角色 IP、系列、稀有度等潮玩信息 | P1/P2，先保留字段口径 |

## 6. 核心页面规格

### 6.1 演示总览页

目标：让评审或项目成员一眼看到 Demo 是否跑通。

核心信息：

| 信息 | 说明 | 优先级 |
| --- | --- | --- |
| 当前设备 | 设备名称、SN、在线/离线 | P0 |
| 当前绑定角色 | 角色名称、角色状态、语音配置状态 | P0 |
| 当前 GPS 状态 | 是否有定位、最近定位时间、是否进入点位范围 | P0 |
| 当前 NFC 状态 | 是否识别标签、标签是否有效、对应点位 | P0 |
| 最近打卡结果 | 成功/失败、时间、点位、触发文案 | P0 |
| 景区知识状态 | 数据集名称、启用状态、最后更新时间 | P0 |

关键交互：

| 操作 | 结果 | 优先级 |
| --- | --- | --- |
| 刷新状态 | 重新拉取设备和打卡状态 | P0 |
| 查看设备详情 | 进入设备详情页 | P0 |
| 查看最近记录 | 进入打卡记录页并自动筛选当前设备 | P0 |
| 进入演示大屏模式 | 隐藏复杂操作，只显示演示状态 | P1 |

验收标准：

| 编号 | 标准 |
| --- | --- |
| A-01 | PC、平板、手机均可查看，不出现核心信息遮挡 |
| A-02 | 设备离线、GPS 无信号、NFC 无效、打卡失败均有明确状态 |
| A-03 | 最近一次成功打卡能展示设备、角色、点位和时间 |

### 6.2 设备列表页

目标：管理一期演示设备，并为后续市场化设备管理保留基础能力。

字段：

| 字段 | 说明 | 优先级 |
| --- | --- | --- |
| 设备名称 | 管理端显示名称 | P0 |
| 设备 SN/ID | 硬件唯一标识 | P0 |
| 在线状态 | 在线、离线、未知 | P0 |
| 绑定角色 | 当前绑定的唯一智能体 | P0 |
| 最近心跳时间 | 判断设备是否可用 | P0 |
| 最近 GPS 状态 | 有定位、无定位、定位过期 | P0 |
| 最近打卡时间 | 最近一次有效打卡 | P0 |

关键交互：

| 操作 | 结果 | 优先级 |
| --- | --- | --- |
| 搜索设备 | 按 SN、名称、角色搜索 | P0 |
| 筛选在线状态 | 快速定位异常设备 | P0 |
| 查看详情 | 进入设备详情页 | P0 |
| 更换绑定角色 | 原厂管理员可操作 | P0 |

验收标准：

| 编号 | 标准 |
| --- | --- |
| A-04 | 管理员可以确认每台硬件当前只绑定一个智能体 |
| A-05 | 离线设备不能被误判为可演示状态 |
| A-06 | 角色绑定变更需要显示操作者和变更时间，便于追溯 |

### 6.3 角色智能体页面

目标：管理课题和市场化共用的角色智能体配置。

字段：

| 字段 | 说明 | 优先级 |
| --- | --- | --- |
| 角色名称 | 对外展示名称 | P0 |
| 角色定位 | 角色 IP、人设摘要、讲解风格 | P0 |
| 人格 Prompt | 智能体基础人格配置 | P0 |
| 语音配置 | voice_id 或语音服务配置引用 | P0 |
| 关联知识 | 景区数据集或知识库引用 | P0 |
| 状态 | 启用、停用、草稿 | P0 |
| 市场化字段 | 系列、稀有度、盲盒编号、收藏标签 | P1/P2 |

关键交互：

| 操作 | 结果 | 优先级 |
| --- | --- | --- |
| 新建角色 | 创建一个可绑定的智能体 | P0 |
| 编辑角色 | 修改人设、Prompt、语音配置 | P0 |
| 启停角色 | 控制是否可绑定到设备 | P0 |
| 查看绑定设备 | 查看当前角色被哪些设备使用 | P0 |

验收标准：

| 编号 | 标准 |
| --- | --- |
| A-07 | 一个设备同一时间只能绑定一个角色 |
| A-08 | 角色停用后不能继续绑定到新设备 |
| A-09 | 已绑定角色的修改需要保留变更记录或至少显示更新时间 |

### 6.4 设备角色绑定页

目标：满足“出厂确认，后期只能原厂指定后台更换”的产品约束。

核心规则：

| 规则 | 说明 | 优先级 |
| --- | --- | --- |
| 单设备单角色 | 每个硬件机器人只能对应一个智能体 | P0 |
| 原厂可更换 | 后期只能由原厂后台指定更换 | P0 |
| 用户不可自由切换 | Demo 阶段不开放用户切换入口 | P0 |
| 绑定可追溯 | 记录绑定人、绑定时间、变更原因 | P0 |

关键交互：

| 操作 | 结果 | 优先级 |
| --- | --- | --- |
| 选择设备 | 进入绑定操作上下文 | P0 |
| 选择角色 | 展示可绑定角色列表 | P0 |
| 确认绑定 | 替换或建立绑定关系 | P0 |
| 查看历史 | 查看最近绑定变更 | P1 |

验收标准：

| 编号 | 标准 |
| --- | --- |
| A-10 | 不存在一个设备同时绑定多个角色的页面状态 |
| A-11 | 绑定成功后设备详情页和演示总览页状态一致 |
| A-12 | 非原厂管理员不能执行角色更换 |

### 6.5 景点点位管理页

目标：支撑“指定地点打卡”的课题 Demo。

字段：

| 字段 | 说明 | 优先级 |
| --- | --- | --- |
| 景点名称 | 打卡点名称 | P0 |
| 景区名称 | 所属景区或演示区域 | P0 |
| 经纬度 | GPS 粗定位判断依据 | P0 |
| GPS 提醒半径 | 进入范围后提示用户靠近 NFC | P0 |
| 打卡成功文案 | 成功后角色播报或页面展示 | P0 |
| 状态 | 启用、停用 | P0 |
| 关联知识 | 该点位对应的景区知识片段 | P0 |

关键交互：

| 操作 | 结果 | 优先级 |
| --- | --- | --- |
| 新建点位 | 增加一个可打卡地点 | P0 |
| 编辑经纬度和半径 | 调整粗定位范围 | P0 |
| 启停点位 | 控制是否参与打卡判断 | P0 |
| 查看关联 NFC | 查看绑定到该点位的标签 | P0 |

验收标准：

| 编号 | 标准 |
| --- | --- |
| A-13 | 至少支持一个指定地点的完整打卡演示 |
| A-14 | GPS 进入范围只触发“靠近提醒”，最终成功以 NFC 为准 |
| A-15 | 点位停用后，设备不能产生该点位的有效打卡 |

### 6.6 NFC 标签管理页

目标：支撑 NFC 精准打卡，避免 GPS 漂移导致误打卡。

字段：

| 字段 | 说明 | 优先级 |
| --- | --- | --- |
| 标签 ID | NFC 标签唯一标识 | P0 |
| 绑定点位 | 标签所属景点点位 | P0 |
| 标签名称 | 管理端可读名称 | P0 |
| 启用状态 | 启用、停用 | P0 |
| 最近识别时间 | 调试使用 | P0 |
| 最近识别设备 | 调试使用 | P0 |

关键交互：

| 操作 | 结果 | 优先级 |
| --- | --- | --- |
| 新增标签 | 录入或绑定 NFC 标签 | P0 |
| 绑定点位 | 将 NFC 标签与景点点位关联 | P0 |
| 停用标签 | 阻止无效标签继续打卡 | P0 |
| 查看打卡记录 | 筛选该标签相关记录 | P0 |

验收标准：

| 编号 | 标准 |
| --- | --- |
| A-16 | NFC 标签未绑定点位时不能产生有效打卡 |
| A-17 | 停用标签被读取时，页面和设备侧均应反馈失败原因 |
| A-18 | 同一标签是否允许绑定多个点位需后续由架构师确认，一期建议不允许 |

### 6.7 打卡记录页

目标：为课题验收和现场调试提供可追溯记录。

字段：

| 字段 | 说明 | 优先级 |
| --- | --- | --- |
| 打卡时间 | 事件发生时间 | P0 |
| 设备 | 设备 SN/名称 | P0 |
| 角色 | 当前绑定角色 | P0 |
| 点位 | 景点点位 | P0 |
| NFC 标签 | 触发标签 | P0 |
| 结果 | 成功、失败、重复、异常 | P0 |
| 失败原因 | GPS 未进入范围、NFC 无效、设备未绑定角色等 | P0 |
| 原始定位质量 | 卫星数、定位时间、精度估计等 | P1 |

关键交互：

| 操作 | 结果 | 优先级 |
| --- | --- | --- |
| 按设备筛选 | 查看某台设备打卡历史 | P0 |
| 按点位筛选 | 查看某点位打卡情况 | P0 |
| 按结果筛选 | 快速定位失败记录 | P0 |
| 导出记录 | 导出课题验收材料 | P1 |

验收标准：

| 编号 | 标准 |
| --- | --- |
| A-19 | 成功和失败记录均可查询 |
| A-20 | 打卡成功记录可以用于证明设备到达指定地点并完成 NFC 精准确认 |
| A-21 | 页面能清楚展示失败原因，避免只看到“失败”但无法定位问题 |

### 6.8 实时演示状态页

目标：用于答辩、现场展示或客户演示。

页面要求：

| 内容 | 说明 | 优先级 |
| --- | --- | --- |
| 当前角色 | 角色头像或名称、人设一句话 | P0 |
| 当前设备 | 在线状态、绑定状态 | P0 |
| 当前点位 | 目标点位、是否进入 GPS 范围 | P0 |
| NFC 状态 | 等待刷卡、识别成功、识别失败 | P0 |
| 打卡结果 | 成功后突出显示点位和角色反馈 | P0 |
| 最近事件 | 最近 3-5 条状态变化 | P1 |

验收标准：

| 编号 | 标准 |
| --- | --- |
| A-22 | 非技术人员能看懂当前演示进行到哪一步 |
| A-23 | 页面适配投屏、平板和手机浏览 |
| A-24 | 不暴露过多调试字段，避免影响展示效果 |

### 6.9 手动模拟打卡页

目标：在硬件未稳定、GPS 信号差或 NFC 调试阶段，仍能完成前后端流程联调。

限制：

| 限制 | 说明 | 优先级 |
| --- | --- | --- |
| 仅测试账号可见 | 普通演示查看者不可见 | P0 |
| 明确标记模拟数据 | 模拟记录不得混入正式验收数据 | P0 |
| 可关闭 | 正式演示时可隐藏该页面 | P0 |

关键交互：

| 操作 | 结果 | 优先级 |
| --- | --- | --- |
| 选择设备 | 模拟指定设备上报 | P0 |
| 选择点位 | 模拟进入某个景点范围 | P0 |
| 选择 NFC 标签 | 模拟读取标签 | P0 |
| 生成模拟记录 | 写入一条带有模拟标识的记录 | P0 |

验收标准：

| 编号 | 标准 |
| --- | --- |
| A-25 | 无硬件时可以验证页面、后端和状态流转 |
| A-26 | 模拟记录与真实设备记录可以明确区分 |
| A-27 | 模拟入口不会出现在公开演示页面中 |

### 6.10 数据集管理页

目标：支撑“基于景区数据打造定制化智能体”的课题主线，让评审能看到智能体不是通用闲聊，而是基于指定景区资料优化。

一期页面不要求做成完整数据标注平台，但必须能展示数据集已经接入、拆分、向量化，并和角色或点位发生关联。

字段：

| 字段 | 说明 | 优先级 |
| --- | --- | --- |
| 数据集名称 | 景区资料或演示数据集名称 | P0 |
| 数据集来源 | 文档、FAQ、讲解词、手工录入等来源说明 | P0 |
| 切分状态 | 未处理、已切分、已向量化、失败 | P0 |
| Chunk 数量 | 展示已拆分片段数量 | P0 |
| 关联角色 | 哪些智能体使用该数据集 | P0 |
| 关联点位 | 哪些景点点位使用该数据集；一期 P0 至少 1 个点位 | P0 |
| 最后更新时间 | 便于判断演示数据是否生效 | P0 |
| 失败原因 | 切分或向量化失败时展示 | P0 |

关键交互：

| 操作 | 结果 | 优先级 |
| --- | --- | --- |
| 查看数据集 | 查看数据集基础状态 | P0 |
| 查看片段摘要 | 查看部分 chunk 标题或摘要 | P0 |
| 关联角色 | 指定角色使用该数据集 | P0 |
| 关联点位 | 指定点位使用该数据集 | P0 |
| 重新处理 | 触发重新切分/向量化，具体实现由架构确认 | P1 |

验收标准：

| 编号 | 标准 |
| --- | --- |
| A-28 | 页面能证明当前角色使用的是指定景区数据集 |
| A-29 | 页面能展示数据集已经完成拆分或向量化状态 |
| A-30 | 景点问答结果可以和数据集或点位形成可解释关系 |
| A-31 | 数据集处理失败时，页面能展示失败状态，不误导为可用 |

## 7. 景区知识与向量库页面说明

用户已确认核心需求 2 优化为：

> 基于景区数据打造定制化智能体，需要用到向量数据库拆分，根据特定数据集优化。

因此这里不再作为“是否做”的待确认项，而是作为课题一期 P0。待架构师和全栈工程师确认的是实现深度：

| 方案 | 页面影响 | 产品判断 |
| --- | --- | --- |
| 方案 A：页面支持上传和重新切分 | 需要数据集上传、切分状态、知识启停、角色关联知识页面 | 产品体验更完整，但工程量更高 |
| 方案 B：页面只展示预置数据集和处理状态 | 页面显示数据集名称、chunk 数量、向量化状态和关联关系 | 更适合一期 Demo，仍能支撑课题表达 |

PM 初步建议：一期采用方案 B，保留“预置数据集 + 状态展示 + 角色/点位关联 + 部分片段摘要”。完整上传、自动切分、重新向量化流程可作为 P1，但架构上必须保留升级路径。

## 13. 当前结论

一期前端产品范围不应只做一个简单后台。至少需要：

1. 可适配 PC、平板、手机的管理页面；
2. 可展示 GPS 粗定位 + NFC 精准打卡状态的演示页面；
3. 可管理设备、角色、绑定、景点、NFC 标签和打卡记录；
4. 可证明“每个硬件机器人只能对应一个智能体”；
5. 可支撑课题主线，同时不破坏市场化后续的 AI 盲盒角色方向。
