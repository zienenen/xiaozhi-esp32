# 安全与数据治理边界

文档状态：confirmed
主责智能体：架构师智能体 + 研发主管智能体
更新时间：2026-07-12

## 0. 阶段结论

本文件只定义一期课题演示所需的最低安全与数据边界。

一期目标是支撑“小智设备 + 自研后端管理端 + 景点数据 + NFC/GPS 校准 + 三端适配页面”的闭环演示，不建设完整商业化安全治理体系。

完整的权限体系、合规审计、密钥轮换、数据生命周期自动化、隐私协议、等保/渗透测试、企业级日志审计、复杂风控策略等内容，统一归入商业化阶段再补充；二期目前不做这些重治理内容。

## 2. 一期数据分类

| 数据类别 | 示例 | 一期处理方式 | 商业化阶段 |
| --- | --- | --- | --- |
| 公开展示数据 | 景点名称、景点简介、演示页面展示内容 | 可在前端展示 | 可补充内容审核与发布流程 |
| 业务配置数据 | 角色 prompt、景区问答 prompt、景点知识库摘要、设备绑定关系 | 存在自研后端，不直接写死在小智官网 | 可补充版本管理、审批、灰度发布 |
| 设备识别数据 | `device_id`、设备 SN、设备绑定状态 | 后端保存，接口按设备鉴权 | 可补充设备证书、动态签名 |
| 设备密钥数据 | `device_token`、小智调用我方接口 token | 环境变量或后端配置保存，日志脱敏 | 可补充密钥轮换、KMS、细粒度授权 |
| 定位与签到数据 | GPS 粗定位、NFC `tag_id`、签到记录、定位质量 | 设备约 10 秒一次上报位置；后端保存最近位置、定位质量和签到时定位点，不保存长期连续轨迹 | 可补充隐私策略、留存周期、删除机制 |
| 演示数据 | 模拟设备、模拟签到、测试账号数据 | 标记来源，避免和真实设备混淆 | 可补充数据隔离环境 |

## 3. 一期最低访问控制

一期只做轻量访问控制，目标是避免接口裸奔和误操作。

管理端：

- 使用演示账号登录。
- 账号密码不得写死在前端代码中。
- 后端通过环境变量或数据库初始化配置管理演示账号。
- 不做复杂 RBAC，不做多租户权限，不做企业 SSO。

设备端：

- 设备调用后端接口时使用 `device_id + device_token`。
- `device_token` 不在日志中明文打印。
- 设备鉴权失败时只返回通用错误，不返回密钥校验细节。

小智官网或小智工具调用我方后端：

- 一期仍依托小智官网作为语音入口和工具调用入口。
- 小智侧只配置调用我方接口所需的工具入口，不承载我方完整业务后台。
- 小智调用我方后端时建议使用轻量 `X-Tool-Token` 或等价静态服务 token。
- 一期不做 OAuth、mTLS、动态签名、复杂网关策略。

## 4. GPS 与 NFC 数据边界

GPS 在一期只用于辅助判断“是否接近景点”，不作为最终签到凭证。

一期约束：

- 不保存连续运动轨迹。
- 设备侧按约 10 秒一次上报 GPS 位置信息和定位质量。
- 后端保存最近一次定位、定位质量、签到时定位点。
- 一期不保存长期连续轨迹，不做高精度轨迹回放。

NFC 在一期作为最终位置校准和签到确认依据。

一期约束：

- NFC 以静态 `tag_id` 绑定景点或打卡点。
- 接口按 `device_id + tag_id + checkin_time` 形成签到事件。
- 静态 NFC 可能被复制的风险一期接受，用于课题演示。
- 动态 NFC、防复制签名、一次性挑战码等商业化能力暂不建设。

## 5. Prompt 与知识库边界

一期的核心理解是：我方自研后端套一层业务管理与知识库服务，小智官网只负责语音入口和工具调用。

一期做法：

- 角色 prompt、景区问答 prompt、景点知识库摘要由我方后端管理。
- 小智官网配置工具入口，调用我方后端接口获取上下文或知识库结果。
- 前端管理端不直接暴露小智侧 token、设备 token、数据库账号等敏感配置。
- 后端接口负责把景点、角色、当前设备状态组合为可供小智调用的上下文。

一期不做：

- 不复刻小智官网全量后台能力。
- 不把全部业务知识手工维护在小智官网。
- 不做复杂 prompt 版本审批、多人协作发布、A/B 实验。

## 6. 日志与审计边界

一期只做排障所需的基础日志，不做完整审计平台。

需要记录：

- 接口调用时间、接口路径、设备编号、结果状态。
- 签到事件、NFC tag 命中结果、GPS 定位质量。
- 数据集导入状态、摘要片段数量、最近更新时间。
- 小智工具调用我方接口的成功或失败状态。

不得记录：

- 明文 `device_token`。
- 明文数据库密码、Django `SECRET_KEY`、小智服务 token。
- 长期连续 GPS 轨迹。

建议处理：

- token 日志统一脱敏为前后少量字符。
- 模拟设备数据增加 `source=simulation` 或等价字段。
- 演示环境日志保留策略以“够排障”为准，不建设审计归档。

## 7. 数据保存与备份边界

一期保存内容：

- 景点数据与知识库摘要。
- 设备绑定信息。
- NFC 标签与景点绑定关系。
- 签到事件。
- 最近定位摘要或签到时定位点。
- 演示账号与基础配置。

一期不保存内容：

- 用户完整连续轨迹。
- 与课题演示无关的个人隐私数据。
- 小智官网账号密码。
- 第三方平台长期凭据明文。

备份策略：

- 一期允许手工数据库备份。
- 不建设自动化多地备份、归档、恢复演练。
- 商业化阶段再补充正式备份恢复、数据留存、删除与审计策略。

## 8. 一期接受的风险

以下风险在一期课题演示阶段接受，但需要在商业化前重新评估：

| 风险点 | 一期处理 | 商业化阶段建议 |
| --- | --- | --- |
| 演示账号权限过粗 | 使用单一演示账号 | 补充 RBAC、多账号、操作审计 |
| 设备 token 静态 | 用户已确认一期接受；以环境变量或数据库保存 | 补充动态签名、密钥轮换、设备证书 |
| NFC tag 可复制 | 课题演示接受 | 补充动态标签、防复制校验 |
| 小智工具调用使用静态 token | 够演示闭环 | 补充网关鉴权、签名、限流 |
| 日志审计较轻 | 只做排障日志 | 补充审计日志、告警、归档 |
| 数据留存策略简单 | 手工备份和清理 | 补充生命周期、删除申请、合规文档 |
| 无正式安全测试 | 研发自测为主 | 补充渗透测试、依赖扫描、安全基线 |

## 9. 二期目前不做的内容

为了避免一期范围失控，以下内容明确不进入当前建设：

- 复杂 RBAC 权限体系。
- 多租户隔离。
- 企业 SSO。
- KMS 或专业密钥管理系统。
- 自动密钥轮换。
- 动态 NFC 防复制体系。
- 完整 GPS 轨迹风控系统。
- 等保、ISO、GDPR 类正式合规体系。
- 安全运营中心、SIEM、专职审计平台。
- 小智官网全量后台复刻。
- 完整商业化隐私协议和用户授权闭环。

这些内容在市场化、商业化、真实游客规模上线前，由产品经理、研发主管、安全负责人重新立项评估。

## 10. 给全栈人员的落地要求

后端：

- 在 `.env.example` 中预留 `DEVICE_TOKEN` 或设备 token 管理说明。
- 在 `.env.example` 中预留 `XIAOZHI_TOOL_TOKEN` 或等价配置。
- 设备接口校验 `device_id + device_token`。
- 小智工具接口校验服务 token。
- 日志中不得打印完整 token。
- GPS 上报按约 10 秒一次位置上报设计，后端保存最近位置和签到时定位点。
- NFC 签到事件要能区分真实设备与模拟设备。

前端：

- 不在前端写死任何 token、数据库连接串、小智账号信息。
- 管理端只展示必要状态、摘要和操作结果。
- 一期可使用演示账号，不做复杂权限页面。

设备模拟器：

- 严格按 [web_api_contract.md](web_api_contract.md) 调用接口。
- 模拟数据标记来源。
- 不生成与真实设备混淆的生产编号。

部署：

- 一期一台云服务器部署。
- `.env` 不提交代码仓库。
- Docker Compose 暂不进入当前范围。
- Nginx/Gunicorn 配置可作为示例，不要求形成完整生产运维体系。

## 11. 当前确认项

已确认：

- 本文件按“一期最低安全与数据边界”定位。
- 完整安全治理、合规审计、复杂权限、密钥轮换等内容二期目前不做，商业化阶段再补。
- 小智官网仍作为一期语音入口和工具入口，我方后端负责 prompt、知识库和业务数据。
- 一期接受静态 `device_token` 和演示账号，不做完整权限体系。
- GPS 按约 10 秒一次上报位置信息；后端保存最近位置和签到时定位点。
- 一期需要公网演示环境，但不建设完整公网生产化治理。

仍需技术验证：

- 小智官网侧工具/MCP 能否稳定调用我方公网 HTTPS 后端接口。
- 公网环境下 CORS、token、超时和错误兜底是否满足演示稳定性。
