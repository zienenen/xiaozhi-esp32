# 盲盒角色智能体旅游打卡 Demo 需求文档

## 1. 项目背景

本 Demo 基于小智 ESP32 开源项目进行二次开发，目标是验证“硬件盲盒角色 IP + 语音智能体 + 景点 GPS 打卡交互”的产品闭环。

产品核心假设：

- 每台硬件机器人对应一个唯一角色 IP。
- 角色智能体基于景区数据集定制，具备独立性格、声音和景区知识能力。
- 景区数据需要经过清洗、拆分、向量化入库，并在对话中用于检索增强。
- 用户不能自行切换角色。
- 原厂后台可在必要时更换设备绑定的角色。
- 旅游景点 Demo 阶段先实现指定地点 GPS 打卡。
- 到达指定地点后，硬件机器人主动触发角色化语音交互。

## 2. 当前开源项目已有基础能力

| 模块 | 已有能力 | 对本 Demo 的价值 |
| --- | --- | --- |
| 语音输入 | 支持麦克风采集、唤醒词、VAD、语音识别链路 | 可直接承载用户和角色智能体的语音对话 |
| 语音输出 | 支持扬声器播放、TTS 音频播放、提示音 | 可用于角色说话、打卡播报和反馈音效 |
| AI 对话链路 | 已有 ASR + LLM + TTS 的实时交互架构 | 可作为多角色智能体的底层交互框架 |
| 网络通信 | 支持 Wi-Fi，部分板卡支持 4G；支持 WebSocket / MQTT+UDP | 可连接后台获取角色配置、知识库和打卡数据 |
| 设备状态机 | 已有启动、联网、待机、聆听、说话、配网、升级等状态 | GPS 到点事件可接入现有状态和交互流程 |
| 显示能力 | 支持 OLED/LCD 状态、文本、表情、通知展示 | 可展示当前角色、打卡成功、景点提示等信息 |
| 本地音效 | 内置成功、错误、提醒等音效资源 | 可用于打卡成功、到点提醒、交互开始提示 |
| MCP 工具系统 | 设备可注册工具供后台/AI 调用 | 可扩展定位查询、打卡触发、设备状态等工具 |
| 多板卡适配 | 已支持大量 ESP32 系列板卡 | 有利于选择合适硬件快速验证 |
| OTA/资源更新 | 支持固件和部分资源更新 | 后续可扩展角色资源、提示语、音效更新 |
| 外设扩展 | 已有 UART、I2C、SPI、按键、灯效、摄像头等接入范式 | GPS 模块可参考 UART 外设方式接入 |

## 3. Demo 产品目标

| 目标 | 说明 | 验收标准 |
| --- | --- | --- |
| 验证角色绑定 | 每台设备出厂绑定一个角色 IP | 设备启动后能获取并使用指定角色配置 |
| 验证定制化智能体 | 基于景区数据集打造角色智能体 | 能基于指定景区资料回答问题，并保持角色口吻 |
| 验证 GPS 打卡 | 设备到达指定景点后自动识别 | 进入配置半径后触发一次打卡事件 |
| 验证景点交互 | 打卡后触发角色化景点介绍或提问 | 到点后机器人主动播报，并可继续问答 |
| 验证最小后台配置 | 后台或配置表可维护设备、角色、景点数据 | 不改固件即可调整角色绑定和景点配置 |

### 4.2.1 景区数据处理链路

| 步骤 | 输入 | 处理 | 输出 | 优先级 |
| --- | --- | --- | --- | --- |
| 1 | 景区原始资料 | 收集景区介绍、景点说明、历史故事、游览规则、FAQ | 原始数据集 | P0 |
| 2 | 原始数据集 | 清洗无关内容、去重、统一格式 | 干净文本数据 | P0 |
| 3 | 干净文本数据 | 按景点、主题、段落长度进行拆分 | 知识片段 chunk | P0 |
| 4 | 知识片段 chunk | 增加 metadata，如 scenic_area_id、spot_id、topic、audience、agent_id | 可过滤知识片段 | P0 |
| 5 | 可过滤知识片段 | 向量化并写入向量数据库 | 向量知识库 | P0 |
| 6 | 用户问题 + 当前景点 | 按语义检索相关片段，并优先过滤当前景点 | 检索上下文 | P0 |
| 7 | 检索上下文 + 角色 prompt | 生成角色化讲解或问答 | 智能体回复 | P0 |

## 7. 非功能需求

| 类别 | 要求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| 兼容性 | 管理页面和打卡页面适配 PC、平板、手机浏览器 | P0 | Chrome / Edge / Safari 主流浏览器可正常访问 |
| 响应式 | 三端页面不需要三套设计，但必须响应式适配 | P0 | 手机端可完成核心查看和配置动作 |
| 性能 | 管理页面常规操作响应不超过 2 秒 | P0 | 列表、详情、保存配置无明显卡顿 |
| 实时性 | GPS 状态和打卡状态允许轻微延迟 | P0 | 一期建议 5-15 秒内刷新或轮询更新 |
| 稳定性 | GPS 漂移不能导致连续重复打卡 | P0 | 同一景点触发后进入冷却或已打卡状态 |
| 安全性 | 原厂管理页面必须登录访问 | P0 | 未登录访问自动跳转登录页 |
| 权限 | 用户不可改绑角色，只有原厂账号可操作 | P0 | 普通演示账号看不到改绑入口 |
| 可配置性 | 角色、设备绑定、景点坐标、半径、文案可配置 | P0 | 不改固件即可调整 Demo 数据 |
| 数据可用性 | 景区资料必须完成清洗、拆分、向量化后才能被智能体使用 | P0 | 后台能看到数据集处理状态 |
| 检索准确性 | 当前景点问答优先召回当前 spot_id 相关内容 | P0 | 到达景点后问相关问题，回答基于该景点资料 |
| 可观测性 | 能查看设备最近 GPS 上报和打卡记录 | P0 | 现场问题能判断是设备、GPS、后台还是配置问题 |
| 容错 | GPS 无效时页面明确显示“未定位/定位无效” | P0 | 不把无效坐标误判为到点 |
| 数据记录 | 关键打卡事件需要落库或持久化 | P1 | 刷新页面后仍能看到打卡记录 |
| 审计 | 原厂改绑角色需记录操作人和时间 | P2 | Demo 可暂缓，商业化阶段补齐 |

## 8. Demo 暂不做范围

| 功能 | 暂不做原因 |
| --- | --- |
| 用户自由切换角色 | 与盲盒唯一角色设定冲突 |
| 角色屏幕头像/动态表情 | 用户已确认 Demo 暂不需要 |
| 完整 App | 一期先用响应式 Web 覆盖 PC/平板/手机 |
| 复杂后台运营系统 | 一期只做 Demo 必需的设备、角色、景点、打卡配置 |
| 盲盒抽取商城 | 当前重点是硬件绑定和角色体验 |
| 角色长期记忆成长 | 复杂度高，非 Demo 必需 |
| 多景区路线规划 | 先验证单点/少量点打卡 |
| 地图导航 | 不是本阶段核心卖点 |
| 成就系统/收集系统 | 可作为后续商业化玩法 |

## 9. 建议的用户体验流程

| 步骤 | 用户行为 / 设备行为 | 系统处理 |
| --- | --- | --- |
| 1 | 用户打开机器人 | 设备启动并联网 |
| 2 | 设备识别自身 device_id | 后台返回绑定的 agent_id |
| 3 | 设备加载角色配置 | 获取角色人设、音色、景区知识库引用 |
| 4 | 用户携带设备前往景点 | GPS 持续更新当前位置 |
| 5 | 设备进入景点半径 | 触发打卡判断 |
| 6 | 设备播放提示音并播报 | 使用角色音色和角色口吻提示到达 |
| 7 | 用户继续提问 | 后台基于角色、当前景点和向量检索结果回答 |
| 8 | 设备记录打卡状态 | 避免短时间重复触发 |
